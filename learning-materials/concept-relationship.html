2核心问题

  1. 关系性：Agent、上下文、Skill 是三个独立概念还是一个概念的三个角度？RAG 又加进来后是什么位置？
  2. 作用性：上下文（而非模型本身）才是决定 Agent 表现的核心因素——这意味着什么？
  3. 演进性：Skill 既然是个文件，它怎么能"越用越聪明"？背后是什么机制？

3通俗解释

一句话定义：四概念之间的关系可以概括为一句话——Skill（持久经验）在被触发的时刻转化为上下文（瞬时信息环境），上下文决定 Agent（执行者）当下怎么想、怎么做；RAG 是"按需供给上下文"的工业实践。

类比：把整个系统比作一个团队——Agent 是干活的实习生，上下文 是他桌上摊开的全部材料，Skill 是公司发给他的 SOP 手册（被夹进材料堆里），RAG 是公司另外给他配的"图书管理员"（缺资料时自动查资料补到桌上）。

类比的局限：把 Agent 比作"实习生"暗示其内部有持续意识在思考。但 LLM 每轮推理都是无状态地重读上下文一次，"持续的智能"是循环叠加的视觉效果，不是真有"小人在想"。这一点和 agent.html 板块 3 的解释相同。

关键特征（咬合关系）：

  • 持久层 vs 瞬时层：Skill 文件（持久）+ RAG 知识库（持久）→ 上下文（瞬时，重建）→ Agent 行动（瞬时）
  • 触发注入：Skill 经 description 匹配后加载进上下文，RAG 在每次提问时检索片段填充上下文
  • 决定输出：上下文之外，对 Agent 而言不存在；质量决定输出质量
  • 闭环演进：行动反馈修订 Skill，Skill 越用越好——这是 Skill 与传统 prompt 最本质的区别

4核心机制 / 组成

概念持久层（持久存在）瞬时层（每次重建）作用
Agent 智能体—运行中的程序/会话自主拆解并完成任务的执行者
上下文—一次推理的输入内容Agent 决策时可见的信息环境
Skill 技能仓库文件 SKILL.md触发后注入上下文沉淀成文件的可复用任务方法
RAG 检索增强向量库 / 知识库检索到的片段进上下文"按需供给上下文"的工业实践

图：Skill 经触发注入上下文 + RAG 按需检索注入上下文 → 上下文构成 Agent 的决策依据 → Agent 行动产生新观察写回上下文 → 执行反馈驱动 Skill 迭代

上下文如何影响 Agent 的工作

  1. 上下文质量 = 决策质量。上下文里若没有任务要求，Agent 就"不知道"要求；若有错误的观察结果，它就基于错误事实行动——垃圾进，垃圾出。
  2. 窗口有限，必须取舍。多步任务的对话历史、工具返回、资料引用会持续累积，逼近窗口上限后系统只能截断或压缩——早期的重要约定（如"报告必须用中文"）可能被丢弃，导致 Agent 后期跑偏。
  3. 位置影响注意力。受 Lost in the Middle 现象影响，塞在上下文中部的关键信息更容易被忽略；这也解释了为什么 Skill 里要把"红线要求"写成显眼的清单放在末尾——自检清单正是在管理这一点。
  4. 上下文是 Agent 唯一的"记忆通道"。外部记忆（文件、数据库、Skill、RAG 知识库）只有被取回、放进上下文，才能真正影响 Agent 的下一步。喂进上下文，知识才生效。

Skill 如何沉淀可复用的任务知识

沉淀维度没有 Skill 时有了 Skill 之后
显性化方法散落在对话记录里，难以复述写成结构化文件（场景/输入/步骤/输出/自检）
复用每次重新口头交代一遍要求语义匹配自动触发，"教一次，到处用"
协作经验无法传递给别人（和未来的自己）项目级目录随仓库共享，同学 clone 即得
演进改了要求没法追踪历史Git 提交历史 = 方法论的进化史，可 diff 可回滚
关键咬合：Skill（持久的经验）在触发时刻转化为上下文（临时的现场信息），上下文塑造 Agent（当下的行为）。三者的关系可以概括为：知识活在文件里，生效在上下文里，落地在行动里。

图读法：这是板块 4 关系图的时序版本——把四个概念咬合的过程按时间展开。Skill 出现在最左侧（被加载）；RAG 紧随其后（按需检索片段）；上下文 出现在装配和回写两个动作里（不是模型本身）；Agent 是中间那位持续循环的"调度员"。读这张图的关键是分清持久层（Skill 文件、RAG 知识库）和瞬时层（上下文、Agent 当前会话）——两者的边界决定了"经验如何沉淀、知识如何生效"。

四步咬合的具体动作

  1. 沉淀（Skill → 文件）：把"概念学习八板块法"写成 concept-learner/SKILL.md，提交进 Git；
  2. 触发与注入（Skill → 上下文）：说"用 concept-learner 学习 Agent"，SKILL.md 的流程要求进入上下文；
  3. 按需检索（RAG → 上下文）：概念相关的资料片段（如 arXiv 论文摘要）被检索出来，与 Skill 一起装入上下文；
  4. 执行（上下文 → Agent 行动）：Agent 按流程检索来源、验证链接、生成 agent.html——期间所有搜索结果、网页内容都在持续写入上下文；
  5. 反馈（行动 → Skill 迭代）：人工核查发现某处类比不妥 → 修改资料，必要时修订 SKILL.md（比如"类比必须说明局限"就是一条经验教训固化成的规则）→ 再次提交。
关系总结：Agent 提供"把事做完"的执行力，上下文提供"当下看见什么"的信息环境，Skill 提供"怎么做才好"的长期经验，RAG 提供"按需补给上下文"的工业实现。四者缺一不可：没有 Agent，方法只是纸面文章；没有上下文管理，执行者很快"失忆"跑偏；没有 Skill，每次都从零开始、经验无法积累；没有 RAG，模型参数外的现场知识就无从进入上下文。

6概念辨析（易混淆 + 使用边界）

易混淆对比表

易混之处四概念中谁负责一句话区别
"Agent 已经知道" vs "Skill 已经知道"前者是模型参数，后者是文件Agent 的"知道"是训练时学到的；Skill 的"知道"是任务方法，不动参数
"上下文里有" vs "RAG 检索到"前者是当下窗口，后者是知识库上下文是临时工作台；RAG 知识库是持久仓库，每次取几页放进工作台
"Skill 触发" vs "RAG 检索"前者匹配任务类型，后者匹配问题内容Skill 是语义匹配 description；RAG 是相似度检索文档片段
"上下文 vs 微调"前者改提问时输入，后者改模型权重上下文每次对话可改；微调重训一次成本高

常见误解清单

  • 误解："四概念彼此独立。" → 正确：四者是咬合关系，缺一会导致整个系统失效——比如没有 RAG，模型参数外的知识就无法进入上下文，Agent 也就看不见。
  • 误解："Skill = 提示词文件。" → 正确：Skill 是结构化、可触发、可多人共享、可版本演进的任务知识包；提示词是单次对话里临时写的话。
  • 误解："RAG 只是搜索。" → 正确：RAG 是检索 + 拼接 + 生成三步——传统搜索止于返回链接，RAG 由 LLM 整合后输出完整答案。

使用边界（四者的局限）

  1. 上下文之外的世界，对 Agent 不存在——再聪明的模型看不到"草稿纸外"的信息；
  2. Skill 不能替代模型能力——Skill 提供经验，不改变模型本身的能力上限；
  3. RAG 的检索质量决定答案质量——检索不到正确片段，模型给再多上下文也没用；
  4. Agent 多步循环会累积错误——幻觉沿循环放大，关键事实要人工复核。

7自测问题（5 题：3 单选 + 2 简答）

1.（单选）"上下文"在四概念咬合关系中的角色，最准确的描述是？

正确答案：B。上下文是瞬时层，承载持久层的输出（Skill 注入、RAG 检索）和 Agent 当前行动的结果。

答错反馈：A（"持久存在的知识库"）混淆了上下文与 RAG 知识库——后者持久，前者瞬时。C（"训练好的模型参数"）混淆了上下文与参数——参数固化在权重里，上下文每次重建。D（"Skill 的别名"）完全错误——Skill 是文件，上下文是运行时输入。

回到正文：板块 3「关键特征」持久层 vs 瞬时层 + 板块 4「核心机制」表格瞬时列。

2.（单选）Skill 的"自动"体现在哪个机制上？

正确答案：B。Agent 根据 description 与当前任务的语义匹配度自主决定是否加载 Skill。

答错反馈：A（"用户必须显式调用"）违背了"声明式触发"的核心——若是显式调用，就只是命令不是 Skill。C（"模型自动重新训练"）完全错误——Skill 不改变参数。D（"系统强制启用"）忽视了"匹配判断"的存在——只有 description 匹配时才加载。

回到正文：skill.html 板块 4「关键机制」声明式触发行。

3.（单选）"喂进上下文，知识才生效"这句话最准确的含义是？

正确答案：C。外部知识（文件、数据库、Skill、RAG 知识库）必须被取回、放进上下文，才能影响 Agent 的下一步决策。

答错反馈：A（"上下文容量大"）是手段不是含义——容量大不等于知识生效。B（"上下文会越用越多"）是现象，不是含义。D（"上下文永久保留知识"）错误——上下文是瞬时的，每轮重建。

回到正文：板块 4「上下文如何影响 Agent 的工作」第 4 条 + 板块 5 时序图中"装配=系统+Skill+检索片段+任务"一行。

4.（简答）用一句话概括四概念（Agent / 上下文 / Skill / RAG）的咬合关系。

正确答案：Skill（持久经验）+ RAG（持久知识库）→ 经触发 / 检索转化为上下文（瞬时信息）→ 上下文塑造 Agent（瞬时行动）→ 行动反馈再迭代 Skill。

常见漏答：① 只提三个概念忘了 RAG——RAG 是补充"按需供给上下文"的工业实现，缺了它关系链就不完整；② 没点出"持久 vs 瞬时"的边界——这才是四概念咬合的本质特征。

回到正文：板块 3「通俗解释」一句话定义 + 板块 4 关系图。

5.（简答）为什么说"Skill 越用越好"？背后是什么机制？

正确答案：Skill 是文件化、可 Git 管版本的任务知识包。Agent 在使用 Skill 中会暴露不足（步骤遗漏、自检缺项、来源红线缺失等），每次使用后的修订以 Git commit 形式沉淀进 Skill 文件，下一次调用时这些经验就自动生效——形成"使用→发现问题→修订→再使用"的闭环，Skill 因此越用越聪明。

常见漏答：① 只说"Skill 会更新"没说"为什么能更新"——关键是 Git 版本化与触发机制；② 没提"闭环"二字——一次性修订不算"越用越好"，必须能持续迭代。

回到正文：板块 4「Skill 如何沉淀可复用的任务知识」表格「演进」行 + 板块 5 时序图右下角虚线注释。
