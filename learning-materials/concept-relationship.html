1一句话总览

Agent 是"执行者"，上下文是它每一步决策时"眼前的世界"，Skill 是写下来、可复用的"做事方法"。
三者的咬合方式：Skill（经验）在合适的时机被注入上下文（信息环境），上下文决定 Agent（行动者）这一步怎么想、怎么做；行动的结果又反过来修订 Skill——形成一个"经验 → 记忆 → 行动 → 更新经验"的闭环。

4上下文如何影响 Agent 的工作

Agent 每一轮"思考"，本质上就是 LLM 对当时上下文做的一次推理。上下文之外的世界，对 Agent 而言不存在。这带来四条直接影响：

  1. 上下文质量 = 决策质量。上下文里若没有任务要求，Agent 就"不知道"要求；若有错误的观察结果，它就基于错误事实行动。垃圾进，垃圾出。
  2. 窗口有限，必须取舍。多步任务的对话历史、工具返回、资料引用会持续累积，逼近窗口上限后系统只能截断或压缩——早期的重要约定（比如"报告必须用中文"）可能被丢弃，导致 Agent 后期跑偏。
  3. 位置影响注意力。受 Lost in the Middle 现象影响，塞在上下文中部的关键信息更容易被忽略；这也解释了为什么 Skill 里要把"红线要求"写成显眼的清单放在末尾——自检清单正是在管理这一点。
  4. 上下文是 Agent 唯一的"记忆通道"。外部记忆（文件、数据库）也只有被取回、放进上下文，才能真正影响 Agent 的下一步。喂进上下文，知识才生效。

5Skill 如何沉淀可复用的任务知识

Skill 解决的是另一个问题：好方法不该每次都重新发明。没有 Skill 时，"怎么把一个概念学透"这件事只存在于某次对话里——换个会话、换个概念，一切从头再来。Skill 把方法沉淀下来：

沉淀维度没有 Skill 时有了 Skill 之后
显性化方法散落在对话记录里，难以复述写成结构化文件（场景/输入/步骤/输出/自检）
复用每次重新口头交代一遍要求语义匹配自动触发，"教一次，到处用"
协作经验无法传递给别人（和未来的自己）项目级目录随仓库共享，同学 clone 即得
演进改了要求没法追踪历史Git 提交历史 = 方法论的进化史，可 diff 可回滚

而 Skill 发挥作用的机制，恰恰又是"进入上下文"——这把三个概念串成了一条线：Skill（持久的经验）在触发时刻转化为上下文（临时的现场信息），上下文塑造 Agent（当下的行为）。三者的关系可以概括为：知识活在文件里，生效在上下文里，落地在行动里。

6一个闭环实例：本次作业

  1. 沉淀（Skill → 文件）：把"概念学习八板块法"写成 concept-learner/SKILL.md，提交进 Git；
  2. 触发与注入（Skill → 上下文）：说"用 concept-learner 学习 Agent"，SKILL.md 的流程要求进入上下文；
  3. 执行（上下文 → Agent 行动）：Agent 按流程检索来源、验证链接、生成 agent.html——期间所有搜索结果、网页内容都在持续写入上下文；
  4. 反馈（行动 → Skill 迭代）：人工核查发现某处类比不妥 → 修改资料，必要时修订 SKILL.md（比如"类比必须说明局限"就是一条经验教训固化成的规则）→ 再次提交。
我的总结：Agent 提供"把事做完"的执行力，上下文提供"当下看见什么"的信息环境，Skill 提供"怎么做才好"的长期经验。三者缺一：没有 Agent，方法只是纸面文章；没有上下文管理，执行者很快"失忆"跑偏；没有 Skill，每次都从零开始、经验无法积累。理解了这三个概念的咬合关系，也就理解了 AI 辅助学习的正确姿势——与其每次求 AI"聪明一点"，不如把好方法沉淀成 Skill，把关键信息管理进上下文，让 Agent 按套路稳定发挥。
