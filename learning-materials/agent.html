Agent（智能体）

1学习目标

  • 能说出 Agent 的定义，以及它和普通"聊天机器人"的本质区别
  • 能列出 Agent 的四个核心组成部分，并说明各自的作用
  • 能描述 Agent Loop（感知—思考—行动循环）是如何运转的
  • 能举出一个 Agent 的具体应用场景，并说明每一步发生了什么
  • 能说出使用 Agent 的两条以上边界（什么情况下不该用）

2核心问题

  1. 同样是调用大模型，为什么有的只能"一问一答"，有的却能"自己把活干完"？差别到底在哪里？
  2. Agent 的"自主性"来自哪里——是模型本身更聪明了，还是外部给了它什么东西？
  3. 任务交给 Agent 就一定能做得更好吗？什么时候反而不如固定流程？

3我的解释

我的理解：大模型本身像一个博学但手脚被绑住的人——它什么都懂，却只能动嘴，不能查资料、不能写文件、不能上网。Agent 就是把这个"人"解放出来：给它接上工具（手脚）、塞给它一份工作记忆（上下文）、再给它一个目标，让它自己拆任务、想办法、动手做、看结果、再调整，循环往复直到把事情做完。

所以判断一个东西是不是 Agent，关键不看它界面长什么样，而看它有没有自主规划 + 循环执行 + 调用工具这三件事。普通聊天机器人一问一答就结束了；Agent 会把"帮我写个报告"这种模糊目标，自己拆成查资料、读文件、写初稿、检查修改一整套动作。

4核心机制 / 组成

组成部分角色（类比）作用
LLM 大模型大脑理解目标、拆解任务、决定下一步做什么
工具 Tools手脚搜索引擎、代码执行、文件读写、API 调用等实际行动能力
上下文与记忆工作台承载"当前能看到的信息"：任务、历史、中间结果；长期记忆需外部存储
规划与循环做事方法感知 → 思考 → 行动 → 观察结果 → 再思考……直到目标达成

Agent Loop 的运转逻辑

  1. 感知：接收目标（如"帮我调研 X 并写摘要"），连同已知信息写入上下文
  2. 思考：LLM 基于上下文推理，规划下一步（"我先搜索 X 的定义"）
  3. 行动：调用工具执行（搜索、读文件、运行代码……）
  4. 观察：把工具返回的结果写回上下文，再回到第 2 步重新思考
  5. 终止：LLM 判断目标已达成（或触发护栏上限），输出最终结果
类比的局限：把 LLM 比作"大脑"容易让人误以为它有持续的意识。实际上每一轮循环里，模型都是无状态地重新读取上下文再做一次推理——"连续的自主性"其实是一圈圈循环叠加出来的效果，而不是模型内部有个"小人"在思考。

5应用场景

场景：用 AI 助手（如 WorkBuddy）完成课程作业"调研一个大数据工具并写成报告"。

循环Agent 在做什么对应机制
第 1 轮把作业目标写入上下文，拆解出计划：先查资料 → 再对比 → 最后成文LLM 规划
第 2 轮调用网络搜索工具查"Spark 架构 官方文档"，拿到若干结果工具调用
第 3 轮调用网页阅读工具读取其中两篇，把要点摘要写回上下文工具 + 上下文累积
第 4 轮发现资料里两个版本说法不一致，追加搜索官方 Release Notes 确认基于观察自我修正
第 5 轮调用文件写入工具生成 report.docx，自检格式后交付多步任务收尾

整个过程用户只说了最初那一句话——目标模糊、步骤繁多、需要边做边调整，正是 Agent 最擅长的任务形态。

6概念辨析与使用边界

对比维度Chatbot 聊天机器人Workflow 工作流Agent 智能体
谁决定步骤用户一步步问开发者预先写死LLM 动态决定
能否用工具通常不能能（固定编排）能（自主选择）
适合的任务问答、闲聊步骤固定的批量任务目标明确但路径不确定的任务
可控性 / 成本高 / 低高 / 中较低 / 较高

容易混淆的点

  • "接了插件的对话助手就是 Agent 吗？" 不一定。若模型只能在你每次提问时被动调一个工具然后回答，仍偏 Assistant；Agent 的标志是自主多步循环。
  • "Agent 比 Workflow 高级，所以都要用 Agent？" 不是。Anthropic 的工程博客明确建议：能用固定工作流解决的任务（如固定格式转换），用 Workflow 更稳定、更便宜、更好调试。
使用边界（什么时候不该用）： ① 高风险操作（删库、对外发消息、花钱）必须加确认护栏，不能放任自主循环；② 幻觉会沿循环累积，多步任务错误率高于单轮问答，关键事实要人工复核；③ 长任务 token 成本高，简单任务用 Agent 是杀鸡用牛刀；④ 无限循环失控风险，需要设置步数 / 时间上限。

7自测问题

1.（判断）只要 AI 应用接入了搜索工具，它就是 Agent。

答：错。判断标准是"自主规划 + 循环执行 + 调用工具"三者齐备。被动地在你提问时调用一次工具、不拆解任务不循环的，只是带工具的助手。

2.（简答）Agent Loop 中"观察结果"这一步为什么重要？

答：工具返回的结果必须写回上下文，LLM 下一轮推理才能基于最新事实决策。没有这一步，Agent 就成了"闭着眼睛做事"，无法根据反馈自我修正。

3.（简答）Workflow 和 Agent 的核心区别是什么？各举一个适合的任务。

答：Workflow 的步骤由开发者预先写死，Agent 的步骤由 LLM 动态决定。固定格式的周报生成适合 Workflow（稳定、便宜）；"帮我调研并写份综述"路径不确定，适合 Agent。

4.（简答）Agent 的"记忆"和它的"上下文"是什么关系？

答：上下文相当于当前这轮推理能看到的工作记忆；跨轮次、超窗口的长期记忆需要存到外部（文件、数据库），需要时再取回放进上下文。长期记忆本身不参与推理，只有进入上下文的部分才生效。

5.（简答）举两条使用 Agent 时的必要护栏，并说明原因。

答：① 高风险操作前人工确认（防误删、防对外发布错误内容）；② 设置最大循环步数 / 超时（防死循环烧 token）；③ 关键事实人工复核（防幻觉多步累积）——任答两条即可。
