2核心问题

  1. 定义性：同样是调用大模型，为什么有的只能"一问一答"，有的却能"自己把活干完"？差别到底在哪里？
  2. 机制性：Agent 的"自主性"来自哪里——是模型本身更聪明了，还是外部给了它某种机制让它能"自己转起来"？
  3. 边界性：任务交给 Agent 就一定能做得更好吗？什么时候反而不如固定流程？

3通俗解释

一句话定义：Agent 是一种能主动规划任务、调用工具、并基于结果自我修正的 AI 执行单元。

类比：可以把它理解为"被解开了手脚的博学助理"——普通大模型像一个博学但手脚被绑住的人，只懂回答；Agent 则是给这个人接上了工具（手脚）、配上了工作台（上下文），再交给它一个目标，剩下的路它自己走。

类比的局限：把人比作 Agent 容易暗示 Agent 内部有持续的"意识"在思考。实际上 LLM 每一轮都是无状态地重新读取上下文再推理一次，"自主性"是一圈圈循环叠加出来的视觉错觉，模型本身没有持续的意志。

关键特征（缺一不可）：

  • 主动规划：自行把模糊目标拆成可执行步骤
  • 调用工具：用工具落地具体动作（不是只动嘴）
  • 循环执行：每一步基于上一步的结果再决策
  • 自我修正：发现错误会调整方案，而不是一路跑到黑

4核心机制 / 组成

组成部分角色（类比）作用
LLM 大模型大脑理解目标、拆解任务、决定下一步做什么
工具 Tools手脚搜索引擎、代码执行、文件读写、API 调用等实际行动能力
上下文与记忆工作台承载"当前能看到的信息"：任务、历史、中间结果；长期记忆需外部存储
规划与循环做事方法感知 → 思考 → 行动 → 观察结果 → 再思考……直到目标达成

Agent Loop 的运转逻辑

  1. 感知：接收目标（如"帮我调研 X 并写摘要"），连同已知信息写入上下文
  2. 思考：LLM 基于上下文推理，规划下一步（"我先搜索 X 的定义"）
  3. 行动：调用工具执行（搜索、读文件、运行代码……）
  4. 观察：把工具返回的结果写回上下文，再回到第 2 步重新思考
  5. 终止：LLM 判断目标已达成（或触发护栏上限），输出最终结果
类比的局限（细化）：把 LLM 比作"大脑"容易让人误以为它有持续的意识。实际上每一轮循环里，模型都是无状态地重新读取上下文再做一次推理——"连续的自主性"其实是一圈圈循环叠加出来的效果，而不是模型内部有个"小人"在思考。

5应用场景

场景：用 AI 助手（如 WorkBuddy）完成课程作业"调研一个大数据工具并写成报告"。

    participant A as Agent
    participant L as LLM
    participant S as 搜索工具
    participant F as 文件系统
    U->>A: 调研XX并写报告
    A->>L: 拆任务→查→对比→写
    loop 思考循环
        L-->>A: 下一步行动
        A->>S: 搜索关键词
        S-->>A: 返回若干结果
        A->>F: 读取历史素材
        F-->>A: 文件内容

    A->>F: 写入 report.docx
    A-->>U: 交付报告+引用
图读法：横轴是角色（U/A/L/S/F），纵轴是时间；每个 ->> 是一次调用、-->> 是一次返回。从上往下读，就能看清 Agent 是怎么把"调研 + 写报告"这种模糊目标，一步步拆成可执行的工具调用，并把每一步的反馈都写回上下文的——这就是 Agent Loop 的时序视角。
循环Agent 在做什么对应机制
第 1 轮把作业目标写入上下文，拆解出计划：先查资料 → 再对比 → 最后成文LLM 规划
第 2 轮调用网络搜索工具查"Spark 架构 官方文档"，拿到若干结果工具调用
第 3 轮调用网页阅读工具读取其中两篇，把要点摘要写回上下文工具 + 上下文累积
第 4 轮发现资料里两个版本说法不一致，追加搜索官方 Release Notes 确认基于观察自我修正
第 5 轮调用文件写入工具生成 report.docx，自检格式后交付多步任务收尾

整个过程用户只说了最初那一句话——目标模糊、步骤繁多、需要边做边调整，正是 Agent 最擅长的任务形态。

6概念辨析（易混淆 + 使用边界）

易混淆对比表

对比维度Chatbot 聊天机器人Workflow 工作流Agent 智能体

常见误解清单

  • 误解："接了插件的对话助手就是 Agent" → 正确：若模型只能在你每次提问时被动调一个工具然后回答，仍是 Assistant；Agent 的标志是自主多步循环。
  • 误解："Agent 比 Workflow 高级，所以都要用 Agent" → 正确：能用固定工作流解决的任务（如固定格式转换），用 Workflow 更稳定、更便宜、更好调试。
  • 误解："Agent 可以无人监管全自动" → 正确：高风险操作必须加护栏；多步循环里幻觉会累积，关键事实仍需人工复核。
  • 误解："Agent 越复杂越聪明越好" → 正确：过度复杂的 Agent 反而更难调试；任务匹配度比模型聪明度更关键。

使用边界（什么时候不该用）

  1. 高风险操作（删库、对外发消息、花钱）必须加确认护栏，不能放任自主循环；
  2. 幻觉会沿循环累积，多步任务错误率高于单轮问答，关键事实要人工复核；
  3. 长任务 token 成本高，简单任务用 Agent 是杀鸡用牛刀；
  4. 无限循环失控风险，需要设置步数 / 时间上限。

7自测问题（5 题：3 单选 + 2 简答）

1.（单选）下列哪一项最能决定一个 AI 应用"是不是 Agent"？

正确答案：B。三件事齐备才是 Agent，少一件都只是普通助手或工具。

答错反馈：你可能误选 A（"接了工具"），因为很多对话助手都能上网搜索；但这只是"能调用工具"，没有"主动规划"和"循环执行"。也常见误选 C（"会用 LLM"），但所有 AI 应用几乎都用 LLM，这并不能区分 Agent。判断 Agent 的标志是自主多步循环。

回到正文：板块 3「关键特征」+ 板块 4「Agent Loop 的运转逻辑」——感知→思考→行动→观察，缺一不可。

2.（单选）Agent Loop 中"观察结果"这一步最不可省略的原因是？

正确答案：C。工具结果必须写回上下文，LLM 下一轮才能基于事实决策。

答错反馈：A（"循环才连贯"）只对了一半，没有观察也能循环，只是循环是闭着眼睛做的。B（"生成最终答案"）把观察当成结束步骤，理解反了——观察发生在每一步之后，是输入不是输出。正确理解：观察是给下一次"思考"喂数据的关键动作。

回到正文：板块 4「Agent Loop 的运转逻辑」第 4 步 + 板块 5 时序图里 -->>A: 返回结果 后接 A->>L: 下一步行动 的回路。

3.（单选）哪种任务最适合用 Agent 而不是 Workflow？

正确答案：B。目标明确但路径不确定，正是 Agent 的强项。

答错反馈：A（"每周生成固定格式周报"）步骤完全固定，Workflow 更合适。C（"把 Excel 转 CSV"）连工具都不需要 Agent 来调度。D（"实时翻译"）追求速度和确定性，应该用 Workflow 或专门 API。判断要点：步骤是否需要 LLM 动态决定。

回到正文：板块 6 易混淆对比表"适合的任务"一行 + 使用边界第 3 条（简单任务用 Agent 是杀鸡用牛刀）。

4.（简答）Agent 的"长期记忆"和"短期上下文"是什么关系？

正确答案：上下文相当于当前这轮推理能看到的"工作台"；跨轮次、超窗口的长期记忆需要存到外部（文件、数据库），需要时再取回放进上下文。长期记忆本身不参与推理，只有进入上下文的部分才生效——"喂进上下文，知识才生效"。

常见漏答：① 把"长期记忆"等同于"训练时学到的知识"——其实训练知识固化在参数里，与本话题的运行时记忆是两回事；② 忘记点出"长期记忆不直接参与推理"这层限制。

回到正文：板块 4 表格「上下文与记忆」一行；详细讨论见 llm-context.html。

5.（简答）举两条 Agent 的必要护栏，并各说明原因。

正确答案：任答两条即可，参考：

  1. 高风险操作前人工确认——防 Agent 自主循环误删库、误发消息、误付款；
  2. 设置最大循环步数 / 超时——防死循环烧光 token；
  3. 关键事实人工复核——防幻觉沿多步累积。

常见漏答：① 只答"加护栏"而不说具体动作——护栏必须可执行（确认按钮 / 步数上限 / 抽样审核），不是空话；② 把"护栏"和"测试"混为一谈——护栏是运行时拦截，测试是发布前验证。

回到正文：板块 6「使用边界」全部 4 条 + 板块 6「常见误解清单」第 3 条。
