大模型的上下文（Context）

由 concept-learner Skill 生成 · 2026-09-03 · 学习深度：入门

1学习目标

  • 能说出"上下文"的准确含义，以及上下文窗口里通常装着哪几类内容
  • 能区分模型的参数知识与上下文信息这两种"知识来源"
  • 能解释上下文窗口为什么有限，以及超出后会发生什么（截断 / 压缩）
  • 能说出"Lost in the Middle"现象及其对写提示词的启示
  • 能解释上下文如何影响 Agent 的工作质量

2核心问题

  1. 为什么 AI 聊久了会"忘记"你开头提的要求——它不是每次都读全部对话吗？
  2. 同一个模型，为什么有的回答像"失忆"，有的却能引用你三天前发的文档？
  3. "上下文"和"训练数据"都是模型的知识，它们到底有什么本质不同？

3我的解释

我的理解：上下文就是 AI 当前可以利用的信息——系统设定、之前的对话、能用的工具说明、你刚发来的资料和问题，全都在里面。模型这一次回答，只根据这些信息作答；不在这份信息里的东西，它一概"看不见"。

上下文有点像模型眼前的一张草稿纸：纸的尺寸（上下文窗口）有限，按 token 计数，写不下的内容会被裁掉或压缩。它最重要的价值，是给模型提供了参数里没有的"现场信息"——今天的日期、你的作业要求、刚检索到的网页。同一个模型有时表现好有时表现差，往往不是它聪明程度变了，而是它"眼前能看到的信息"变了。

4核心机制 / 组成

三种"知识来源"的对比

维度参数知识（训练）上下文（本次窗口）外部记忆（RAG / 文件）
类比长期记忆（背下来的书）短期工作记忆（眼前的草稿纸）图书馆（要用才去查）
更新方式重新训练 / 微调，慢且贵每次对话即时更新随时增删，与模型无关
时效性止步于训练截止日实时（可含刚检索的内容）实时
容量极大（固化在参数里）有限（几 K～1M token）无限，按需取用

关键现象与机制

  • 窗口有限，按 token 计：不同模型窗口从几千到上百万 token 不等；中文一个汉字通常约 1～2 个 token，1 万字对话≈1.5 万 token 起。
  • 超出窗口怎么办：要么截断（丢掉最旧的内容——这就是"聊久了忘记开头"的原因），要么压缩/摘要（把早期对话总结成一段塞回去，省空间但有损）。
  • Lost in the Middle：研究发现模型对开头和结尾的信息记得最牢，塞在中间的内容容易被忽略。写提示词时应把最重要的要求和资料放在开头或结尾。
  • 注意力机制：模型通过注意力对窗口内所有 token 建立关联——上下文里的每一段文字都在互相"竞争"注意力，无关内容越多，关键信息被稀释得越厉害。
类比的局限：把上下文比作"草稿纸"会让人以为信息可以随便擦写。实际上每轮推理时上下文是整体重建的（历史对话会原样重新输入一遍），"擦掉"只是不再携带，而 token 成本是按每次全部输入计算的——所以长对话越聊越贵、越慢。

5应用场景

场景：让 AI 帮你改一份 8000 字的课程报告（真实高频场景）。

  1. 你把报告全文粘贴进对话框，附一句"帮我把第二部分改得更学术一点"——报告全文 + 指令此刻全部进入了上下文；
  2. AI 能精准改写，因为它"眼前"能看到全文（这比它参数里的任何写作知识都关键）；
  3. 接着你连续问了十几个别的问题，对话越滚越长；
  4. 你再问"刚才报告第三段的结论帮我也润色一下"——此时报告全文可能已被挤出窗口（被截断或压缩），AI 开始答非所问，甚至一本正经地"编"出第三段内容（幻觉）；
  5. 正确姿势：开一个新对话重新贴原文，或使用支持文件挂载 / 记忆检索的工具，让系统在需要时把原文重新取回放进上下文。

这个场景说明：同一台模型，上下文组织得好坏直接决定输出质量——模型没变，变的是它"眼前能看到什么"。

6概念辨析与使用边界

易混概念区别一句话
上下文 vs 训练数据训练数据在训练时固化进参数、回答时不可见；上下文是回答这一刻摆在眼前的现场信息
上下文窗口 vs 内存（RAM）类比相似（都讲容量上限），但窗口不"驻留"——每轮推理都重新完整输入一遍，成本按次数累加
RAG vs 微调RAG 是"考试前把资料带进考场"（进上下文）；微调是"考前把资料背进脑子"（进参数）。前者即时、可撤；后者持久、昂贵
上下文 vs 记忆功能很多产品的"记忆"是外挂系统：把要点存进数据库，下次对话自动取回、再注入上下文——窗口内仍是当下这一次

常见误解与使用边界

  • 误解："窗口 128K，我塞 10 万字它就全能记住。" 记得进 ≠ 记得牢：中间内容容易被忽略（Lost in the Middle），关键信息要放开头/结尾。
  • 误解："上下文长 = 模型聪明。" 窗口只是"能看多少"，推理能力由模型本身决定；长窗口塞满噪声反而稀释注意力、降低表现。
使用边界：① 长文档优先"按需检索注入"，而不是整包塞入；② 多轮长任务要主动开新会话或做摘要压缩；③ 涉及精确引用的内容（数据、条款、代码）尽量重贴原文，不要依赖模型对早期上下文的"记忆"。

7自测问题

1.（简答）上下文窗口里通常装着哪几类内容？

答：系统提示、对话历史、工具/Skill 定义说明、检索到的外部资料、当前输入（五类，见第 4 板块示意图）。

2.（简答）为什么 AI 聊久了会忘记你最初提的要求？

答：对话持续累积，总 token 超出上下文窗口上限后，系统会截断或压缩最早的内容，最初的要求可能已被丢弃或摘要得面目全非。

3.（简答）参数知识和上下文信息有什么本质区别？各举一例。

答：参数知识是训练时固化进模型权重的长期知识（如"Python 的语法"），推理时只读不写；上下文是本次对话现场提供的信息（如"你刚贴的报告原文"），每次对话重新构建、可即时增删。

4.（简答）Lost in the Middle 现象是什么？对写提示词有什么启示？

答：模型对窗口开头与结尾的信息利用率高，中间部分容易被忽略。启示：核心指令和关键资料放在开头或结尾，长资料中间不放关键信息；无关内容尽量精简，避免稀释注意力。

5.（选择）想让 AI 准确回答你公司内部文档的问题，最合适的做法是？
A. 微调模型　B. 把文档检索后注入上下文（RAG）　C. 换更大的模型　D. 多问几遍

答：B。内部文档属于模型参数里没有的实时信息，按需检索注入上下文即可即时生效；微调昂贵且更新慢，换模型解决不了"没见过这份文档"的问题。
