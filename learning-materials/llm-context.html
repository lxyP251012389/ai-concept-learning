大模型的上下文（Context）

由 concept-learner Skill 生成 · 2026-09-10 二次修订 · 学习深度：入门

1学习目标

  • 能说出"上下文"的准确含义，并区分上下文与训练数据这两种"知识来源"
  • 能列出上下文窗口里通常装载的几类内容（系统提示、对话历史、工具说明、检索资料、当前输入）
  • 能解释上下文窗口为什么有限、超出后会截断或压缩
  • 能描述"Lost in the Middle"现象及其对写提示词的启示
  • 能说明上下文如何影响 Agent 的工作质量（详见 agent.html）

2核心问题

  1. 事实性：上下文和训练数据都能让模型"知道"一些事，它们的本质区别是什么？
  2. 机制性：为什么 AI 聊久了会"忘记"开头的要求，背后的工程机制是什么？
  3. 应用性：同一台模型，为什么有时回答精准、却答非所问——差别到底来自模型本身还是上下文？

3通俗解释

一句话定义：上下文是大模型在本次回答时能够看见的全部信息，包括系统设定、对话历史、工具说明、检索到的资料和当前用户输入。

类比：可以把它理解为模型眼前的"草稿纸"——纸上写什么，模型才能据此作答；纸外的内容，对它而言不存在。同一台模型配上不同草稿纸，表现可能天差地别。

类比的局限：把上下文比作"草稿纸"会让人误以为内容可以随时擦写。实际上每轮推理时，上下文是整体重新输入的——历史对话会原样重新送一遍，token 成本按每次全部内容累加，所以长对话越聊越贵、越聊越慢。

关键特征：

  • 有限性：窗口有上限，按 token 计数（中文 1 字≈1.5 token），超出后截断或压缩
  • 现场性：上下文承载的是"当下这一刻"的信息，可包含模型参数里没有的最新内容
  • 位置敏感：模型对开头和结尾的信息利用率高，中间部分易被忽略（Lost in the Middle）
  • 决定输出：上下文之外的世界，对模型而言不存在；质量决定输出质量

4核心机制 / 组成

三种"知识来源"的对比

维度参数知识（训练）上下文（本次窗口）外部记忆（RAG / 文件）
类比长期记忆（背下来的书）短期工作记忆（眼前草稿纸）图书馆（要用才去查）
更新方式重新训练 / 微调，慢且贵每次对话即时更新随时增删，与模型无关
时效性止步于训练截止日实时（可含刚检索的内容）实时
容量极大（固化在参数里）有限（几 K～1M token）无限，按需取用

关键现象与机制

  • 窗口有限，按 token 计：不同模型窗口从几千到上百万 token 不等；中文 1 字通常约 1.5 token，1 万字对话≈1.5 万 token 起。
  • 超出窗口怎么办：要么截断（丢掉最旧的内容——这就是"聊久了忘记开头"的原因），要么压缩/摘要（把早期对话总结成一段塞回去，省空间但有损）。
  • Lost in the Middle：研究发现模型对开头和结尾的信息记得最牢，塞在中间的内容容易被忽略。写提示词时应把最重要的要求和资料放在开头或结尾。
  • 注意力机制：模型通过注意力对窗口内所有 token 建立关联——上下文里的每一段文字都在互相"竞争"注意力，无关内容越多，关键信息被稀释得越厉害。
类比的局限（细化）：把上下文比作"草稿纸"会让人以为信息可以随时擦写。实际上每轮推理时上下文是整体重新输入的（历史对话会原样重新送一遍），"擦掉"只是不再携带，而 token 成本按每次全部输入累加——所以长对话越聊越贵、越慢。

5应用场景

场景：让 AI 帮你改一份 8000 字的课程报告（真实高频场景）。

图：长报告改写时的上下文装配与窗口压力Mermaid · sequenceDiagram
sequenceDiagram
    participant U as 用户
    participant A as Agent
    participant L as LLM
    participant C as 上下文窗口
    U->>A: 把第二部分改学术一点
    Note over A,C: 报告全文(~12k token)+指令进上下文
    A->>L: 基于完整上下文推理
    L-->>A: 改写后内容
    A-->>U: 返回修改
    Note over L,C: 若报告>窗口
需 RAG 分段送入
或先摘要再改
图读法：注意 Note over A,C 那段——上下文（不是模型本身）才是这次推理的"工作台"：报告全文 1.2 万 token + 指令 30 token，模型"眼前能看到"的就这么多。如果报告再长一些（比如 5 万字），超过了模型窗口，就得靠 RAG 分段送入 或先做摘要，否则模型会"看不到"开头的内容，Lost in the Middle 效应会让它忘掉最早的要求。
  1. 你把报告全文粘贴进对话框，附一句"帮我把第二部分改得更学术一点"——报告全文 + 指令此刻全部进入了上下文；
  2. AI 能精准改写，因为它"眼前"能看到全文（这比它参数里的任何写作知识都关键）；
  3. 接着你连续问了十几个别的问题，对话越滚越长；
  4. 你再问"刚才报告第三段的结论帮我也润色一下"——此时报告全文可能已被挤出窗口（被截断或压缩），AI 开始答非所问，甚至一本正经地"编"出第三段内容（幻觉）；
  5. 正确姿势：开一个新对话重新贴原文，或使用支持文件挂载 / 记忆检索的工具，让系统在需要时把原文重新取回放进上下文。

这个场景说明：同一台模型，上下文组织得好坏直接决定输出质量——模型没变，变的是它"眼前能看到什么"。

6概念辨析（易混淆 + 使用边界）

易混淆对比表

易混概念区别一句话
上下文 vs 训练数据训练数据在训练时固化进参数、回答时不可见；上下文是回答这一刻摆在眼前的现场信息
上下文窗口 vs 内存（RAM）类比相似（都讲容量上限），但窗口不"驻留"——每轮推理都重新完整输入一遍，成本按次数累加
RAG vs 微调RAG 是"考试前把资料带进考场"（进上下文）；微调是"考前把资料背进脑子"（进参数）。前者即时、可撤；后者持久、昂贵
上下文 vs 记忆功能很多产品的"记忆"是外挂系统：把要点存进数据库，下次对话自动取回、再注入上下文——窗口内仍是当下这一次

常见误解清单

  • 误解："窗口 128K，我塞 10 万字它就全能记住。" → 正确：记得进 ≠ 记得牢。中间内容容易被忽略（Lost in the Middle），关键信息要放开头/结尾。
  • 误解："上下文长 = 模型聪明。" → 正确：窗口只是"能看多少"，推理能力由模型本身决定；长窗口塞满噪声反而稀释注意力、降低表现。
  • 误解："给上下文越多越好。" → 正确：垃圾进、垃圾出——无关内容会挤掉关键信息的注意力配额。

使用边界（什么时候不该过度依赖）

  1. 长文档应"按需检索注入"，而不是整包塞入（参考 rag.html 的 RAG 思路）；
  2. 多轮长任务要主动开新会话，或做摘要压缩，避免早期指令被截断；
  3. 涉及精确引用的内容（数据、条款、代码）尽量重贴原文，不要依赖模型对早期上下文的"记忆"。

2.（单选）AI 聊久了"忘记"你最初提的要求，最主要的原因是？

3.（单选）想让 AI 准确回答公司内部文档的问题，最合适的做法是？
A. 微调模型　B. 把文档检索后注入上下文（RAG）　C. 换更大的模型　D. 多问几遍

正确答案：B。内部文档是模型参数里没有的实时信息，检索注入上下文即可即时生效。

4.（简答）"Lost in the Middle"现象是什么？对写提示词有什么具体启示？

正确答案：模型对上下文窗口开头与结尾的信息记最牢，中间部分容易被忽略。启示：核心指令和关键资料放在开头或结尾；长资料中间不要塞关键信息；无关内容尽量精简，避免稀释注意力。

常见漏答：① 只回答现象本身，没提到"启示"——题目要的是工程含义；② 把现象归因于"窗口太小"——其实是位置效应，与容量无直接关系。

回到正文：板块 4「关键现象与机制」第 3 条 + 板块 6 常见误解第 1 条。

5.（简答）参数知识和上下文信息有什么本质区别？各举一个典型例子。

正确答案：参数知识是训练时固化进模型权重的长期知识（如"Python 语法"），推理时只读不写；上下文是本次对话现场提供的临时信息（如"你刚贴的报告原文"），每次对话重新构建、可即时增删。

常见漏答：① 把"训练数据"等同于"上下文"——训练数据进入参数后已不可单独取出来看；② 没给出具体例子——例子能让答案显得具体而非抽象。
