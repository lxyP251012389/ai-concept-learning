  3. RAG 和"用搜索引擎自己查资料再粘给 AI"看起来很像，它们的差别在哪？

3我的解释

我的理解：RAG = 让 LLM 在回答之前，先去"查资料"，再把查到的内容连同问题一起拼进上下文，最后才生成回答。它解决的问题特别直接——模型的参数知识停在训练截止日，对内部文档、私域知识、时效性内容一无所知；与其昂贵地微调或重训模型，不如在每次提问时"现查现用"。

举个身边的例子：老师让你写一篇关于"2026 年最新的大数据法规"的小论文。如果只用普通 AI 问，它会用训练截止日之前的旧信息糊弄你；用 RAG，系统会先去搜最新的法规数据库、把相关条款找出来，**把这些现场信息塞进上下文**，AI 才有依据写出当下正确的小论文。这就是"检索 → 增强上下文 → 生成"三步走的精髓——它补的就是之前学的"上下文"那一课的短板：上下文里没有的知识对模型等于不存在。

5应用场景

场景：用 AI 助手帮你做"课程问答机器人"——同学问课程相关问题，机器人只引用课件、教材、老师讲义作答。

  1. 课程资料预处理：把所有 PDF 课件、教材章节、老师讲义切成小段，编码为向量，存入向量数据库（这是 RAG 的关键资产）
  2. 同学提问："第二章里支持向量机的对偶问题怎么推导？"
  3. 检索阶段：把问题转成向量，到向量库里找出最相关的 3-5 段教材内容（可能是支持向量机原始定义页+对偶问题推导页+例题页）
  4. 拼接阶段：把这些片段+问题+系统提示（"你只允许引用上述内容作答，不知道就说不知道"）拼成一个 prompt
  5. 生成阶段：LLM 基于这些"现场材料"写出答案，并在每个关键句后标注引用编号
  6. 如果同学追问，模型基于同样检索到的素材继续回答——始终不脱离一手知识

对比"直接问普通 AI"——普通 AI 会一本正经地用参数里模糊的 SVM 记忆给出答案，经常出错；用 RAG 后回答的每一步推导都能追溯到教材页码，对错一目了然。

6概念辨析与使用边界

易混概念区别一句话
RAG vs 微调RAG 改的是"考试时带的资料"（上下文），微调改的是"脑子里背的内容"（参数）
RAG vs 搜索引擎搜索引擎返回链接让用户自己读；RAG 把检索结果直接喂给 LLM，由 LLM 整合成完整答案
RAG vs 长上下文长上下文是"整本教材摆桌上"（贵、易超出窗口）；RAG 是"先查索引再带几页进考场"（精准、省 token）
RAG vs Agent 工具调用RAG 是"被设计好的检索→生成流水线"；Agent 则会按需动态决定何时检索、用哪个工具、检索几次

常见误解与使用边界

  • 误解："RAG 让 AI 永远正确。" 不是。RAG 只保证"依据给定的资料"，资料本身错就跟着错；模型仍可能在整合时遗漏或扭曲检索结果。
  • 误解："RAG 一定要用向量数据库。" 检索手段多种多样：关键词、BM25、Elasticsearch、API 调用都行，向量检索只是当前最流行的一种。
使用边界：① 检索不到相关资料时，RAG 不如直接让 LLM 自由发挥（瞎答也比"我说不知道"有时更有用）；② 检索结果过多会稀释上下文，反而降低质量，要限制 Top-K；③ 模型需要被训练/提示"只引用给定资料作答，不知道就说不知道"，否则它还是会跑出去胡编；④ 资料源必须新鲜且权威，否则 RAG 拉的是最新的谣言。

7自测问题

1.（简答）RAG 的四个核心步骤是什么？分别解决什么问题？

答：① 提问（拿到问题）；② 检索（在知识库里找相关片段，解决"参数里没有"的问题）；③ 拼上下文（把问题和检索片段拼成 LLM 的 Prompt，解决"现场信息怎么喂进去"的问题）；④ 生成（LLM 基于拼好的上下文作答，解决"现场信息怎么用上"的问题）。

2.（简答）RAG、微调和长上下文三种"让模型掌握新知识"的方法各有什么取舍？

答：RAG：即时更新、成本中等、改的是每次提问的上下文；微调：耗时长、贵、改的是模型参数（长期记忆）；长上下文：实现最简单但受窗口限制、token 成本高、知识"塞"在 prompt 里。三者常组合使用。

3.（选择）"把 8000 字课程讲义整段贴给 AI 提问"算 RAG 吗？
A. 算，是简化的 RAG　B. 不算，是长上下文　C. 算，是检索的特例　D. 都不算

答：B。整段粘贴没有"按问题检索相关片段"这一步，只是把所有可用知识一股脑塞进上下文窗口。真正的 RAG 必须有"针对当前问题检索最相关片段"的过程。

4.（简答）RAG 和搜索引擎的本质区别是什么？

答：搜索引擎返回"链接列表"让用户自己点开读；RAG 把检索结果直接喂给 LLM，由 LLM 综合成一段完整答案，并可附带引用——RAG 是"自动读完资料再写摘要"，搜索引擎是"给本书让你自己读"。

5.（简答）RAG 不是万能的——什么时候用 RAG 比直接问 LLM 更糟？

答：① 检索库没有相关资料时（强行 RAG 会让模型无依据作答或答非所问）；② 检索质量差、Top-K 命中无关内容时（反而污染上下文）；③ 文档质量差/有错误时（模型会被错误信息引导，比直接问更糟）；④ 极简单问答（用 RAG 反而绕远、增加延迟和成本）。
